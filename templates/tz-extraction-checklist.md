# Чек-лист извлечения требований из ТЗ

Используй при анализе любого входного документа. Заполни все секции; если данных нет — явно пиши «не указано» + `TODO`.

## 1. Мета

- [ ] Название сервиса / модуля
- [ ] Версия / этап (MVP, prod, pilot)
- [ ] Владелец / заказчик
- [ ] Связанные системы (Bitrix, 1C, CRM, mobile app, …)

## 2. Назначение

- [ ] Бизнес-цель (зачем сервис)
- [ ] Пользователи / роли (клиент, агент, оператор, система)
- [ ] Сценарии использования (user stories или use cases)

## 3. Границы

- [ ] In scope — что входит
- [ ] Out of scope — что явно не входит
- [ ] Ограничения (SLA, rate limit, объём данных)

## 4. Интеграция

- [ ] Точка входа (Bitrix module, standalone API, gateway)
- [ ] Аутентификация / авторизация
- [ ] Форматы обмена (JSON, XML — обычно JSON)
- [ ] Синхронность (sync REST / async webhook / очередь)

## 5. Ресурсы и операции

Для каждой сущности из ТЗ:

| Сущность | Операции (CRUD + custom) | Кто вызывает | Примечания |
|----------|--------------------------|--------------|------------|
| … | … | … | … |

## 6. Модели данных

- [ ] Поля сущностей (тип, обязательность, пример)
- [ ] Связи между сущностями
- [ ] Enum / статусы
- [ ] Правила валидации из ТЗ

## 7. Нефункциональные

- [ ] Безопасность (ПДн, маскирование)
- [ ] Логирование / audit trail
- [ ] Коды ошибок и тексты для пользователя

## 8. Открытые вопросы

Список `TODO` для аналитика / архитектора перед финализацией OpenAPI.
**Только** то, чего реально нет в ТЗ. Не заменять пробелы догадками.

## 9. Сверка полноты (Coverage Audit) — ОБЯЗАТЕЛЬНО

Перед сохранением analysis пройди **исходный ТЗ** секция за секцией:

- [ ] Каждый endpoint (method + path) из ТЗ → есть в analysis
- [ ] Каждое поле из таблиц данных → есть в Data Models
- [ ] Каждый enum / статус → перечислен дословно
- [ ] Каждое бизнес-правило / кейс (fallback, приоритет) → есть в Business Rules
- [ ] Каждый NFR → есть в Non-functional
- [ ] Каждый код ошибки / auth → отражён
- [ ] **Ничего не добавлено** от себя (проверка: «Добавлено от себя: нет»)

Таблица traceability:

| # | Раздел ТЗ | Требование | Где в analysis | Статус |
|---|-----------|------------|----------------|--------|
| 1 | … | … | … | ✅ / ❌ / TODO |

Если статус ❌ — исправь analysis до финализации.
